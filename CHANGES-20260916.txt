MMcasesBot - 16/09/2026 revision

1. OPEN CASE READING
   - Today's normal cases continue as before.
   - Older OPEN SPFO Balance cases are also read until their balance workflow is complete.
   - Older OPEN SPFO Interest Problem cases continue daily until resolved.
   - Older OPEN JSU cases are also read (JSU Balance / JSU Retirement / JSU umbrella service).

2. SHORT CONSOLE
   - Normal polling/debug chatter is hidden in local Windows mode.
   - Main case line format:
     CASE | <id> | Service: <service> | Assigned: <name> | WhatsApp: <status> | Mail: <status>
   - An unchanged case line is not printed again on every scheduler cycle.
   - SID/SPFO CAPTCHA prompts and real failures remain visible.

3. MEMBERSHIP
   - Remains inside MMcasesBot (not a separate running project).
   - Data-first order remains:
     INDoS No + INDoS Password -> DG Profile -> Sea Service -> SID -> Course Details -> Sheets -> MM Customer -> Mail/WhatsApp.
   - Stored INDoS Password reading is more tolerant of MUI/React sibling value rendering.
   - DG Home / Update Seafarer Profile recovery is more resilient after Sea Service/eLearning pages.
   - DG Sea Service repeated header rows are ignored.
   - Selenium timeout messages are shortened so capability dumps do not flood the console.
   - Missing Membership credential/field reason is shown as one short Membership line.

4. SHEETS
   - Customer Profile keeps INDoS No, INDoS Password, SID No, SID Issue Date, SID Expiry Date, etc.
   - Course Details remains one row per course.
   - Sea Service remains one row per service/voyage.

NOTE: Source syntax was checked in the build environment. Full Maven packaging could not be run there because Maven is not installed; RUN-NOW.bat performs a clean Maven build on the Windows PC using IntelliJ's bundled Maven.
